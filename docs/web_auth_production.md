# Включение web-авторизации на production

## Перед публикацией

Сначала создайте резервную копию БД. После размещения файлов, но **до переключения пользователей на новый интерфейс**, создайте первого администратора из CLI:

```bash
cd /var/www/html/vr/calltrack
php scripts/create_first_web_admin.php admin@example.com "ФИО администратора"
```

PIN вводится интерактивно без отображения и не попадает в аргументы процесса или Git. Скрипт откажется создавать второго первоначального администратора.

## Миграция

Таблицы создаются автоматически при первом обращении к `web_auth_api.php` или при запуске CLI-скрипта:

* `web_users`: ID, ФИО, уникальный email, хеш PIN, роль `admin|manager`, активность, даты создания/изменения и последнего входа;
* `web_login_attempts`: email, SHA-256 IP и время попытки для ограничения перебора PIN.

Создаются уникальный индекс `uk_web_users_login` и индексы `idx_web_users_active`, `idx_web_login_attempt`. Устаревшие поле и индекс ручной привязки менеджера удаляются автоматически.

После создания администратора откройте web-интерфейс, войдите и создайте остальные учётные записи через **Админ-панель → Пользователи**. Для роли «Менеджер» обязательно выберите существующего менеджера Calltrack.

Если пользователь не может войти, безопасно назначьте новый PIN из CLI:

```bash
php scripts/reset_web_user_pin.php LOGIN
```

Команда сохраняет новый `password_hash` и не изменяет остальные поля web-пользователя. Для входа используется именно PIN web-пользователя, а не пароль его почтового ящика.
