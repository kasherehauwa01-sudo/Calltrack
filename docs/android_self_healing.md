# Self-healing Android-приложения

## Архитектура до изменений

Calltrack уже использовал постоянный `CallTrackingService` с `START_STICKY`, минутной локальной меткой активности, `BOOT_COMPLETED` receiver и уникальный 15-минутный `CalltrackStabilityWorker`. Worker одновременно пытался запускать сервис, синхронизировал очередь и отправлял телеметрию. `Application` восстанавливал только periodic work. `onDestroy()` и `onTaskRemoved()` лишь писали диагностику. Обновление APK не обрабатывалось.

Основные разрывы: boot receiver не инициировал сервис сразу; отсутствовал `MY_PACKAGE_REPLACED`; остановка сервиса не планировала восстановление; запуск, синхронизация и контроль были связаны в одном worker; не было ограничения restart loop; logout не отменял фоновые работы; диагностика не объясняла попытки восстановления.

## Новая архитектура

`CalltrackRecoveryManager` — единая точка принятия решений. Он работает только при наличии сохранённого auth token и разрешений чтения телефона/журнала звонков. Менеджер:

1. поддерживает единственный periodic watchdog;
2. пытается запустить foreground service;
3. ставит единственную recovery-задачу с exponential backoff, если немедленный запуск запрещён;
4. ставит единственную network-constrained задачу отправки pending calls и существующей телеметрии;
5. отменяет пользовательские фоновые задачи при logout.

`CalltrackStabilityWorker` раз в 15 минут проверяет не процесс, а минутный heartbeat сервиса. Метка старше трёх минут запускает восстановление с причиной `WATCHDOG`. WorkManager выполняется неточно: Android может отложить запуск из-за Doze, квот или ограничений производителя.

После трёх попыток за 30 минут новые старты временно подавляются. Пишутся `recovery_loop_detected` и ошибка. После пяти минут стабильных heartbeat окно попыток сбрасывается. Глобальный `UncaughtExceptionHandler` для немедленного рестарта не добавлялся.

## Точки восстановления

| Сценарий | Как обнаруживается | Как восстанавливается | Ограничения Android |
|---|---|---|---|
| Загрузка устройства | `BOOT_COMPLETED` | `recover(DEVICE_BOOT)`, watchdog, sync и допустимый FGS start | Receiver придёт только после разблокировки, если она требуется ОС; не придёт после Force Stop |
| Обновление APK | `MY_PACKAGE_REPLACED` | `recover(PACKAGE_REPLACED)` | Не работает при отключённом приложении/Force Stop |
| Уничтожение сервиса | `START_STICKY`, `onDestroy()` | системный sticky restart и `recover(SERVICE_DESTROYED)` | `onDestroy()` не гарантирован, поэтому остаётся watchdog |
| Удаление из Recent Apps | `onTaskRemoved()` и heartbeat | recovery + watchdog | Поведение FGS зависит от прошивки производителя |
| Уничтожение процесса/crash | новый процесс `Application.onCreate()` или пропавший heartbeat | `PROCESS_RESTART` либо watchdog | Фоновый FGS start может быть запрещён Android 12+; применяется backoff |
| Нет сети | network constraint уникального sync worker | отправка очереди и heartbeat после появления сети | Срок запуска определяет WorkManager/Doze |
| Повторные восстановления | окно счётчика в diagnostics | максимум 3 попытки за 30 минут, затем backoff | Следующая попытка после выхода из окна/системного запуска |
| Logout | отсутствие auth token | workers отменяются, tracking не восстанавливается | — |
| Force Stop | системное состояние stopped | автоматическое восстановление не выполняется | Это намеренное ограничение Android до ручного запуска пользователем |

## Практический срок восстановления

Boot, обновление, штатный `onDestroy()`/`onTaskRemoved()` и запуск процесса вызывают recovery сразу. Если callbacks не были вызваны, ближайшая независимая проверка — periodic WorkManager с интервалом 15 минут. **Android не гарантирует максимальное фактическое время**: Doze, квоты, Force Stop и ограничения Xiaomi/Redmi/POCO/Realme/Oppo/Vivo/Huawei/Honor могут отложить или полностью заблокировать фоновые события. Поэтому корректная гарантия — восстановление на ближайшем разрешённом системой запуске watchdog, обычно после следующего 15-минутного окна, но без жёсткой верхней границы.

Приложение показывает владельцам агрессивных прошивок рекомендацию включить «Автозапуск» и разрешить работу в фоне. Никаких vendor-specific скрытых intent или обхода Force Stop нет. UI из receiver/worker не открывается.
